# 后台模型用途的推荐请求配置

2026-10-10。状态：用户要求已记录，设计待落实；本次只改文档，没有新增 API 或改变运行行为。代码核对基线为 `eb4f271d1fdaccb1536ca293505f2c5a22b0e14b`。

## 已确认要求

- 对话以外的模型用途默认使用 Core 提供的推荐请求配置；应用不维护另一份推荐参数。
- 用户可以主动修改记忆提取、视觉回退等后台用途的请求参数，但必须先配置满足用途的模型。应用入口的显示不能代替 Core 的类型、能力和参数校验。
- 支持恢复默认。恢复删除该用途的自定义覆盖，不将当前默认 JSON 复制为固定配置；不更换模型、恢复提示词或修改个人空间策略。
- 对话请求参数与后台用途独立。选择“跟随对话”只继承模型，不继承对话的采样、输出、扩展参数或流式偏好。
- 默认配置与自定义覆盖需可区分。应用只保存、传输自定义部分，不重复携带 Core 内置推荐值。

后台编辑器必须由用户主动打开，不能默认展开。就地展开或弹窗由应用决定，当前仍待用户确认；这一呈现选择不进入 Core。

## 现有实现与缺口

| 代码位置 | 当前事实 |
| --- | --- |
| `crates/momo-core/src/response.rs`、`orchestration/generation.rs::route_parameters` | `momo.model_routes` 已允许视觉、记忆提取和 NSG 治理用途分别传模型及可选生成参数；不需要为 JSON 编辑另造生成引擎。 |
| `orchestration/generation.rs::route_parameters`、`governance.rs` | 路由参数接受个人空间覆盖策略治理。仅传模型也会生成治理后的参数，其中未传温度得到 `None`；这不是按用途读取一份完整推荐配置。 |
| `orchestration/ddm.rs`、`vision.rs` | DDM 和旧视觉网关路径各有温度 `0.0` 的内部默认；DDM 默认输出预算受能力和 4096 上限约束，旧视觉路径使用 1024。这些是真实用途默认，不能将 0 误当成应用的“未设置”。 |
| `orchestration/generation.rs::generate_response_completion`、`model_registry/vision.rs` | DDM 的调用默认会被路由结果覆盖；配置视觉连接使用传入的路由参数。模型选择与默认参数路径因此需要统一，不能只给页面加编辑框。 |
| `orchestration/maintenance.rs` | 记忆和 NSG 维护复用各自提示词空间，未给路由时有维护参数回退；当前没有供应用读取的统一用途推荐请求资源。 |
| `api/runtime_api/embeddings.rs`、`orchestration/generation.rs::resolve_embedding_selection` | 向量化已有独立 profile、索引和查询契约；当前对话选择只暴露模型与维数，不支持任意向量化请求 JSON。生成路由参数不能直接用于 embedding。 |

上一轮增加 `momo.embedding` 是为了让配置的向量化模型实际进入已有 NSG 索引与检索流程；没有另写向量引擎。推荐请求配置是本轮新要求，不能把已有路由覆盖接口说成已经完整实现。

## 拟实施边界

Core 统一解析“用途推荐值 → 自定义覆盖 → 个人空间策略及模型能力约束”。具体推荐数值以现有用途契约为依据，在 Core 实施时核对并验证；本设计不提前指定新的采样值。仅选择模型、显式传空覆盖、恢复默认三种情况都必须保留该用途的推荐行为。

Core 需提供应用可读取的用途配置描述，包括推荐值、可修改字段、参数约束及来源；这里不预定不存在的 HTTP 路径。推荐参数属于内核可信默认，自定义参数仍经过既有覆盖策略。被策略忽略、拒绝或被预算限制的参数应能向调用者说明，不能显示为已生效。

生成请求的温度、Top P、最大输出及扩展参数复用现有契约；字段未指定表示继承用途默认，不能用 0 作为空值。最大输出必须为正整数并受模型预算限制。模型、消息、输入、凭据、地址、工具编排和内部请求标记由 Core 或宿主管理，不能由用途参数 JSON 改写；后台流式方式仍由用途执行契约决定。

向量化需单独描述可调整字段和恢复语义，不能接收生成采样参数。任何影响向量兼容性的配置均纳入既有 profile 标识，索引和查询使用相同有效配置，不能混用旧向量。不支持的字段应明确拒绝，而不是将任意 JSON 透传给服务商。

未修改的配置继续跟随 Core 推荐值；自定义部分保持独立。恢复只删除该用途覆盖，后续新请求使用当时有效默认。同一请求 ID 的重试、已捕获的维护批次仍沿用首次有效配置，不能因恢复或推荐值更新改变重试内容。复用既有持久化、来源和请求快照能力，不增加应用业务数据库依赖。

MOC 中的配置携带自定义覆盖，不烘焙 Core 内置推荐 JSON；已有模型选择和参数组的归属不因这一功能改变。容器与宿主导出仍沿用 [模型连接边界](model_connections.md)，不增加凭据导出。

## 实施验收（尚未执行）

- 独立 Core 调用者未传用途参数时也得到用途推荐配置；配置模型不会意外清掉用途默认。
- 各用途覆盖互不串用，对话参数不进入后台；类型错误、越界和受限参数均按契约处理。
- 删除覆盖后恢复有效默认；模型选择、提示词、个人空间策略、资产和既有请求快照保持各自语义。
- 推荐值读取与实际请求一致；重试及维护批次保持首次配置。
- 向量化默认、覆盖和恢复均保持索引与查询兼容性；失败不污染已有索引。
- 无应用 UI 或 Web 配置文件依赖，必要改动在 Core 独立提交、验证；不以网页测试代替内核验证。
