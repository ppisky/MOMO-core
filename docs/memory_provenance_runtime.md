# 记忆身份与来源运行时 Profile 1

状态：2026-09-30 已实现并完成本机回归；源代码、迁移和说明纳入同一版本追踪。

## 运行时边界

本 Profile 对应 `momo.memory-provenance/1`。它扩展本机管理 API、Patch 的可选证据引用、
记忆快照内的来源文件以及响应审计；不增加 `momo.responses/1.0` 请求字段。
原有 `relations.characters`、`source_character_ids` 继续表示关联，不升级为可信作者。

完成响应时，SQLite 在同一事务写入助手消息、维护轮、请求重放和 `response_evidence`。
证据记录当时的个人 Space、原始对话 Space、对话、角色、实际消息 ID、助手/角色配置版本。
工具续接标为 `tool`，不会虚构用户消息。角色切换和提示词变化不回填旧证据。
默认助手使用已有角色资源：本机为个人 Space 选择一个 `character_id`；未显式选角色的新会话
使用该映射，未配置映射时仍拒绝无角色的新会话。改变默认选择不修改既有会话身份。

## 记录修订与证据

DMW 使用 `config/provenance.json`，NSG 使用 `rules/provenance.json`。文件分别属于各自 MOC
模块。严格解析器拒绝未知版本、字段及断裂的逐记录修订链。模型 Patch 不能直接写这些文件。

每次内容修改保留父修订、内容哈希、操作 ID、提案组件、触发方式、协调者、授权依据、
实际维护提示词与配置。原始证据集合在修订中保留；审批追加动作，不把模型提案改成用户原创。
NSG 候选的历史在批准/拒绝后继续保留。手工编辑没有对话出处时保持未知，不制造消息引用。
内容与来源一起进入现有 prepared commit；后台维护和 Patch Review 使用已有 SQL 持久恢复。
普通手工写入仍采用已有文件事务/回滚边界，不宣称所有管理操作已经具备进程崩溃原子性。

DMW/NSG 的每个 Patch item 可增加 `evidence_refs: [<captured response evidence ID>]`。
运行时验证引用属于本批可信证据；模型不能签发来源或批准。明确引用只是可追踪的支持声明，
不证明其内容为真。未提供引用的兼容 Patch 标为批次输入来源，不能声称精确到事实的独立支持。
已有参考记录的原始证据与父版本一并保留，读取旧记忆不会新造一个独立观察事件。

自动批次按写 Space、维护种类及捕获的身份/连续情境分组，不把角色切换前后的轮次混为同一
身份。默认仍为各 12 轮；不足阈值的尾批可手工 drain。已持久化批次继续复用原证据和配置。
模型只能修改属于当前身份、符合当前适用范围的既有记录；跨角色读取权限不授予写权限。

## 共享、资格筛选与场景

`RecordPolicy` 包含递增 `revision`、本地 `local_space_id`、用户 `personal_space_id`、
`owner_character_id`、显式 `readers`、`continuity_ids`、`function_ids`、`fact_kind`、
`subjects`、`participants`、`responsible_characters` 以及可选 `valid_from / valid_until`。
`fact_kind` 为 `experience / relationship / commitment / preference / knowledge / rule / unknown`。
NSG 规则必须显式限定连续情境/世界。名称相同的 `graph_id` 不是适用映射。

原生响应在宿主给定的 Space 内检索，然后统一检查记录策略、旧注入限制、来源状态与修订。
不合格记录不能进入正文或 MO State。默认未绑定的历史记录不会自动共享；已有明确的
会话和角色双绑定的未追踪旧记录可保留本地使用，但未知来源不进入状态投影。已有来源历史却
没有本机策略的记录（包括导入记录）不能借旧绑定恢复授权。管理检索仍可不带身份查看数据。

合格记录以 `Space / dmw或nsg / local-ID` 区分，附身份视角、主体、参与者、责任人与证据可用性。
不把原始对话文本或消息引用随共享正文暴露。外部经历和共享知识可以作为上下文，不能改变
当前助手的亲历、关系或承诺状态。来源及正文以不可拆分单元参与最终 token 裁剪。

每个个人 Space/角色/连续情境保存独立场景。默认连续情境 ID 是会话 ID；宿主可明确把两个
会话映射到同一情境。后台 current 文档更新进入对应分区，不覆盖 Space 全局场景。
MO State 的观察哈希绑定资格结果与身份；DDM 的资格键绑定身份和策略版本，不复用旧授权的迟滞。
完成响应的 request-ID 重放仍返回其历史结果，不被后续策略变化改写。

## 本机管理接口

这些路由位于既有 loopback 信任边界，宿主负责用户授权；不是公网多租户权限系统。

| 方法与路径 | 请求 |
| --- | --- |
| `GET /v1/memory/provenance` | Query：`space_id`、可选 `semantic_graph`（默认 false） |
| `PUT /v1/memory/record-policy` | `space_id`、`semantic_graph`、`record_id`、完整 `policy` |
| `PUT /v1/memory/identity-binding` | `conversation_space_id`、`conversation_id`、`continuity_id`、可选 `function_id` |
| `PUT /v1/memory/default-assistant` | `personal_space_id`、`character_id` |
| `POST /v1/memory/evidence/control` | `conversation_id`、`stop_maintenance`、`revoke` |

首次策略 revision 必须为 1，之后每次加 1。撤销共享可用下一版本移除 reader；导入的授权不继承，
需本机重新设置策略。清空某模块同时清掉其来源文件，另一模块不受影响。

删除聊天保留记忆，原消息不再活动可读时标为 `source_deleted`；删除快照不算可用证据。
`stop_maintenance` 停止该来源的后续提炼并清理相关未提交批次；`revoke` 撤销其证据使用。
两者独立于删除聊天，并保存本机控制审计。已经准备的文件提交先恢复，再执行来源控制。
精确引用记录仍有其他有效支持时可以保留；只有批次级来源的混合记录在部分撤销后保守停止注入。
这些操作不声称完成所有磁盘副本的安全擦除。

MOC 保留原始 Space、身份和证据，不用 `space_map` 重写历史。导入追加目的地记录并取消
携带的本机授权；无法与可信本机证据匹配时标为 `external_unresolved`，不假装已验证。

## 上下文窗口

`PUT /v1/runtime-settings` 的完整资源可包含：

```json
"history_window": { "enabled": true, "trigger_turns": 12, "evict_turns": 2 }
```

每次组装请求按完整用户/助手问答计数：累计 12 轮后移出最旧 2 轮，随后每新增 2 轮再移出
2 轮。保留当前未完成的用户输入；不删除数据库消息，不确认维护批次。token 预算继续作为
最终硬上限。触发范围 2–1000，淘汰数量必须大于 0 且小于触发数量；可关闭此窗口策略。

### 角色判断与召回接入（2026-09-30）

响应按角色资源哈希在 SQLite `memory_character_profiles` 保存去重、不可覆盖的角色正文快照。
提炼输入 `character_contexts` 按证据引用对应历史版本，不以当前角色卡替换旧证据的人设。
旧数据缺少历史快照时明确标为不可用；不补造历史。此表是内部持久数据，不增加配置文件入口。

Distiller 结合捕获的人设、既有角色/关系记忆和本批证据判断权重与关联。任务完成与情感意义
分别判断：结束的任务移除已失效的待办保护，仍有依据的依恋、信任、遗憾等继续保留。
模型不得把上下文未展示或近期未提及当成不重要。人物判断仍由模型完成，MFM 保持确定性执行。

原生 DMW 在排序前完成记录资格筛选，并以对应身份分区的当前场景/线索提供引用召回入口。
不会先用全局场景召回，再在输出中替换场景。场景引用在展示裁剪前解析；Hot Memory 最多占
DMW 正文预算的 45%，剩余预算留给长期记忆；带身份的长期事实按完整文档选择，不截成片段。
状态观察保存完整的合格场景，提示词裁剪不改变场景事实。对身份隔离的维护批次也使用此路径。

活跃记忆的实质命中独立于展示预算，预算不足不会成为未命中的理由。其他场景或长期关系
中的引用仍提供保护，但不会冒充当前角色本轮的命中；已归档记录的关键词提及不自动恢复它。
默认上下文窗口已改为 12/2，提炼仍按非重叠 12 轮批次。生命周期沿用已有可配置权重规则，
未增加按 120 轮统一淘汰或让归档自动复活的规则。

上述行为由本机回归场景验证；角色意义判断的质量仍需要真实模型和长对话评估，提示词要求
及模拟测试不等于证明每次模型判断都正确。

回归覆盖来源随响应原子写入与重放、历史身份分批、聊天删除/停止提炼/撤销的区别、
跨角色读写与外部经历投影、跨 Space 同 ID、场景隔离、部分提交恢复、MOC 授权降级、
严格解析以及上下文完整裁剪。本轮使用离线测试与模拟模型端点，没有消耗真实模型调用。
记录的主体与支持关系仍需要宿主/作者正确标注；代码不能保证自然语言事实本身正确。
MOC 多模块整体崩溃原子性、故事时间语义和按容量回收不属于此 Profile。
