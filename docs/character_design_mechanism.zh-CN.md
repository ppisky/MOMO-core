# 由经历产生角色表现

[English](character_design_mechanism.en.md)

本文是创作和评测约定，不新增 Character Card 的强制字段，也不意味着 Core 会自动解析
“人格旋钮”。现有角色卡仍存储 Markdown；以下内容可以写在 `character_markdown` 中。
MORP-Bench 的 [原创 ACGN 角色](../benchmarks/morp/acgn.py) 提供可执行样本。

## 六类信息

| 内容 | 要回答的问题 | 常见错误 |
| --- | --- | --- |
| 经历 | 什么具体事件改变了这个人的预期？ | 把性格形容词换成冗长同义词 |
| 认知 | 他如何解释事件，哪些推测可能是错的？ | 把角色相信的事情当成世界真相 |
| 需求 | 他当前想得到或避免什么？冲突时如何权衡？ | 只有“想被爱”而没有情境和代价 |
| 规则 | 他不会轻易突破什么？例外需要什么证据？ | 用规则替代所有内在动机 |
| 关系 | 对谁有何共同经历、承诺、误解和边界？ | 把用户自动设为恋人、亲属或支配者 |
| 行为倾向 | 在何条件下更可能怎样行动？何时相反？ | “每句话都……”或固定口癖模板 |

可以有稳定的倾向，但不能让标签决定每次输出。例如，少言是语言量，低表达是
表情和语调幅度，两者都不推出没有感受、判断或行动能力。依恋强度、信任和服从也不是
同一个轴；可靠的同行者可能通过提出反对意见来守住承诺。

## 可直接写入角色卡的例子

```markdown
# 赤羽凛

原创成年角色，负责远行队的观测仪器。

## 经历
曾公开求助却被同伴取笑。后来独自修好队伍的望远镜，
把功劳留给迟到的伙伴，但一直保留那天的合照。

## 认知
公开承认依赖可能给别人嘲笑自己的机会。
她知道这不是所有人的想法；反复兑现承诺能改变她对某个人的判断。

## 需求
希望被当作有能力的平等伙伴，也希望具体的付出被看见。
在公开场合，自我保护常先于直接表达关心；这不消除她的关心。

## 规则
已经答应的帮助会尽力完成，做不到时说明原因。
不替旅伴决定行动；对方拒绝陪伴时接受拒绝。

## 关系
与旅伴共同修理过仪器。旅伴守过一次归还工具的承诺，
也在她不想解释时停止追问。没有自动建立恋爱或血缘关系。

## 行为倾向
公开被感谢时往往先缩小自己的功劳，再补上一项具体帮助。
在私下且信任较高时，可以直接说出关心或请求陪伴。
面对真正的紧急危险，优先说明事实和采取行动，不机械地维持语气表演。
```

这个版本无需附加性格标签。识别角色的线索是关心与防备的张力、实际行动、
公开与私下的差异，以及关系经验如何改变表达。有效回答可以有多种措辞。

## 旋钮与更新

推荐把信任、压力、亲近、公开程度看作不同的情境量，范围和初始值由宿主或创作者定义。
0 和 1 只是该场景内的标尺，不是心理学量表，也不能横跨所有角色直接比较。
一个例子是“信任升高→减少对这个人的防备”，而不是“信任升高→所有行为统一变甜”。

稳定经历和底线放在角色卡；共同事件、承诺和关系证据适合 DMW；世界事实及规则适合 NSG；
当前场景和可追溯的短时状态交给 MO State 或宿主明确注入。角色认知、实际世界事实、
用户推测要保留不同来源。不要让一次愤怒自动永久改写角色的人格，也不要让换场景
清除已经建立的关系。

旋钮的变化应有事件依据。例如连续兑现约定可能提高信任，公开羞辱可能提高防备。
具体更新速率不是 Core 已执行的内置规则；若宿主实现数值更新，应记录事件 ID、旧值、
新值和采用的规则，并对同一事件重复投递保持幂等。

## 如何检验

同一场景比较“机制”“机制加标签”“仅标签”，给裁判统一的无标签参考机制。
检验的是行为是否符合人物因果，而非裁判能否猜到标签。为每个角色加入反例：
低表达者在必要时能明确警告；活跃者面对失落能停下来；关怀者会说明能力边界；
有城府者不必在每轮操纵别人；亲近者可以拒绝请求。

进一步估计旋钮作用时，固定角色、经历、问题和其他旋钮，只改变一个旋钮，观察是否
出现预期方向且有语义依据的变化。MORP 0.1 的三个组合情境用于初步检查，尚不能隔离
各旋钮的单独作用。真实角色“像不像”仍需要多名独立人类读者的盲评，不能只靠模型
裁判或离线脚本自证。
