## 修复后正式复测

最终代码用全新 revision 和 Space 重跑 `momo/extracted`、horizon 24、中英双语子集。完整 6 题集严格 MORP 得分为 **100/100**，覆盖率 **6/6（100%）**；update、reasoning、social 三个已选维度均为 100，中英文切片均为 100。四条客观题由确定性字段规则评分，两条关系边界题由 Codex assistant 按冻结 rubric 做带原文引证的人工裁决，没有使用 A/B 评审模型。维护屏障平均 10.59 秒、p95 11.50 秒；完整尝试 p95 30.98 秒。

随后对更正承诺和关系推理 4 条客观题各执行 3 次独立重复。第一轮为 83.33/100，暴露一次标识截断和一次跨语言漏召回；修复后第二轮为 91.67/100，又暴露一次连续空补丁；加入空补丁复核后，第三轮为 **100/100，12/12 有效**。第三轮维护屏障 p95 14.30 秒，完整尝试 p95 28.88 秒。所有失败报告均保留，没有用重跑覆盖。

本轮针对根因补充了以下通用约束：

- DMW 索引正文自然语言词项，并为中文等非 ASCII 连续文本生成二元词项；无直接词法命中且文档语言与查询不同时，只回填最多两条高价值活动记忆，同语言负查询仍保持精确。
- DMW 输出中的长型不透明标识必须逐字来自维护输入；截断或新造标识会触发有界修复，而不是写入错误记忆。
- 非空维护批次第一次返回空补丁时复核一次；第二次仍为空才确认消费，避免随机漏写已明确的持久事实。
- 混合检索先为 NSG 保留预算，再把 NSG 未使用的 token 归还 DMW；维护按 DMW、NSG 顺序确认，NSG 失败不会回滚已完成的 DMW 进度。
- 候选提示仅暴露 `eNNNN` 事件来源，不再把 Space UUID 当证据；MORP 时间字段在只出现一个 `HH:MM` 时做与标准答案无关的原子化。

正式报告为 `.codex-tmp/morp-self-grade-fix-20260907/final-full-v6.report.json`，12 次稳定性报告为 `.codex-tmp/morp-self-grade-fix-20260907/objective-stability-final6-r3.report.json`。两份报告的发布状态仍是 `provisional_synthetic_not_human_calibrated`。

## 更正先前评价

此前 5.8/10、7.4/10 等架构评分是主观判断，没有固定权重、业务验收线或统计校准，不能当作成熟度实测。两位外部模型仅审阅证据摘要，也没有独立检查整个实现。应以具体行为和发布条件替代小数点评分。

旧冬储题存在语义歧义：习惯或计划加上季节开始，不必然表示搬运已经执行。将未知直接判为事实错误会混入评分偏差。这不否认旧运行暴露的召回、Draft 可见性与来源追踪问题，但不应从单个歧义题的 0 分推广出整体产品失效。

## 本轮改动

- MORP 正式更名释义为 MOMO Role-playing，并新增 0.2 角色扮演集：6 个机制族、两种相反结局、context/extracted 两类依赖，共 24 个投影。每条同时保留客观字段和角色盲审，避免把事实问答满分当成角色扮演满分。
- 场景计划支持 7 臂因果矩阵，分别开关 DMW、NSG 与 MO State；臂顺序显式保存并按 case/repeat 轮换。完整上下文只作为同模型上限控制，不再与换模型结果混成 MOMO 贡献。
- MO State 新增 `active` / `shadow` 注入模式。检索或状态编译降级时不注入；审计绑定本次真实检索子集的 SHA-256、组件数量和来源 Space，以便定位反馈放大链的起点。
- 回复审计记录实际检索的 ID、类型、来源 Space 与估算 token，不复制记忆正文。角色测试运行器将每轮请求审计和状态审计写入 case 检查点。

- DMW 直接检索先比较明确热引用和不同有效关键词的命中数量，再比较原有权重。减少高权重的部分匹配挤掉正确人物与物品组合；重复标签不增加匹配数量。
- 索引补充正文中明确出现的字母数字编号，按完整词匹配。例如 S17 只出现在 Mara 记录正文中、没有写入别名时，也能召回；S170 不会误命中 S17。正文更正后重建派生索引，移除旧编号；不修改源记忆和权限。
- 模型调用名额改为每 Space 一个前台名额、一个维护名额。先前前台需要获得两个名额，会被正在执行的维护挡住；现在两个维护路由共享后台名额。后台吞吐可能降低，上游网关限流仍可能导致前台排队；这不是已通过负载测试的 SLA。
- 提取提示明确：个人习惯、计划和承诺可以作为带来源、条件和执行状态的叙事事实留在 DMW；已确认世界规则仍由 NSG 治理。时间到来不能自动变成已执行事件。
- 新增 `stress` 套件：16 条投影，4 个语义机制，每个机制有两种相反结果及 context/extracted 两种路径。唯一改变的末尾证据必须改变答案；输出 schema 不泄露正负分支。
- 原生全开测试在第 12/24/36 轮排空维护，确保真的跨过维护周期。检查点恢复先完成尚未结束的排空再输入下一轮，避免恢复时跳过边界。
- 单独统计周期维护等待时间，并在失败记录中保留已经发生的维护等待数据。
- 修复评分报告把缺失/报错结果标成 complete 的问题。零分惩罚保持不变，执行状态改为 incomplete_execution；HTTP 错误额外保存状态码，不保存远端错误正文。

## 验证边界

rc.2 当前代码通过 225 项 Rust 测试、98 项 Python 测试、21 项离线运行契约、严格 Clippy、
Rust 格式检查与 rustdoc 构建。它们验证实现约束，不代表开放场景中的模型生成质量达到 100%。

0.2 角色套件已生成 24-case 数据并离线验证。七臂 recorded 计划需要 168 次候选调用；旧 live 计划需要 4200 次。推荐的单机制、单依赖、三臂 core 计划只需 6 次候选调用，维护调用另计。本轮没有把离线计划或 mock 回复计为新模型成绩。

Qwen 和 DeepSeek 各执行 8 条完整上下文控制题，均为 8/8。这个结果说明这些有限的确定性题目能被模型解答；MOMO 是否保留相同信息，需要另外检查原生跨维护、跨会话运行。四个机制仍是回归测试的起点，不足以代表完整角色扮演业务。

同次完整上下文运行，Qwen 平均完整回复 11.312 秒，DeepSeek 平均 1.727 秒。这个差异来自实际模型与配置路径（包括思考设置、网络等），不是 MOMO 开销；只有 8 次，不是业务尾延迟承诺。

原生全开规划了 execution 的两个分支。第一分支输入了 36 轮，第 12 和 24 轮维护屏障分别用时 91.398 和 118.013 秒；第三次屏障被服务端 120 秒超时终止，日志明确为 HTTP 504，整个尝试耗时 634.559 秒。尚未执行最终问答，事实准确率不可计算。第二分支已开始输入，发现第一分支超时后主动停止，不继续消耗同类调用。报告为 1 error / 1 missing，而不是两道题事实均答错。

这次原生运行使用本轮的检索排序与个人承诺提示改动，发生在前后台名额隔离、正文编号索引修复之前，不能拿它证明最终代码的端到端质量或延迟。最终构建仅在重启后对留存记忆做了一次 scoped retrieval 验证，能够读取 Mara/S17 的尚未执行计划；未完成的维护仍没有写入末轮完成事实。该检查是组件验证，不是新鲜端到端通过。

本轮产物目录：`.codex-tmp/morp-stress-v020`。A/B 结果为 `a.report.json`、`b.report.json`；原生最终解释使用 `native.corrected-status.report.json`，早先 `native.partial.report.json` 保留了状态修复前的报告。旧数据集 manifest 的 horizon 参数继承了 CLI 默认值，实际所有 stress 历史均为 36；新 build 已修正该套件的 provenance，旧实验不覆盖。

## 延迟是否可接受

旧样本的完整回复约 4.2–4.8 秒。作为文字角色聊天可以进入试用，但未测首字延迟、并发 p95/p99、维护争用和真实对话长度，不能承诺业务 SLA。整段 36 轮或 12 轮测试的总时间不是单条消息等待时间。

维护几十秒如果在后台运行，可作为异步工作接受；如果每次回复或用户新开会话必须同步等待，则会明显影响体验。强制排空是测试一致性屏障，需要与普通前台路径分别报告。

建议以以下数值作为待确认的产品验收目标，而非行业事实或已经达成的指标：文字聊天首字 p95 不超过 2 秒、固定长度回复完成 p95 不超过 8 秒；正常回复不等待整批维护；跨会话需要最新事实时有可观察的待同步状态。应以真实目标设备、网络、模型和并发重新测量。

## 正式发布仍缺少的证据

| 项目 | 可执行的验收条件 | 当前状态 |
|---|---|---|
| 跨会话连续性 | 对确认事件、撤销和未知的成对案例固定种子多次运行，单列每个分支，不能用未知题掩盖召回失败 | 4 条客观题 × 3 次已通过，仍需扩大未调优集 |
| 组件贡献 | 相同模型、历史、预算下比较完整上下文、DMW、NSG、组合及全开 | 未完成完整析因 |
| 治理生命周期 | Draft 默认不可读，显式作者晋升后可读，冲突形成候选，重启不改变权限 | 有组件测试，缺业务全链路覆盖 |
| 来源追踪 | 从实际检索记录回溯原始事件，不使用 Space UUID 代替事件 ID | 本子集已闭合，扩大集待验证 |
| 延迟与成本 | 前台首字/完成分位数、后台等待、模型耗时、维护和 embedding 成本分别报告 | 已报告小样本完成延迟，TTFT、并发与完整成本仍缺失 |
| 故障恢复 | 维护超时、非法补丁、空补丁、进程退出、重试后不丢已确认事件且不重复写入 | 非法/空补丁及 DMW 成功后 NSG 失败已有测试，进程故障注入待补 |
| 角色业务质量 | 未参与调优的复杂角色、真实多会话和独立人工抽检 | 未完成 |

不承诺“怎么跑都满分”。固定回归集可以要求持续通过；开放角色扮演的验收应报告成功率、失败类型和适用范围。任何通过条件都应在新一轮运行前确定，不能为了达标删除失败题或修改答案。
